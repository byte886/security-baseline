# 唯一主口令：又强又记得住的人设方案

> 解决一个具体矛盾：**复杂密码记不住，简单密码不安全。** 答案是"只记一句够长的口令短语"，而不是记很多个复杂密码。
> 配套：主口令解锁哪些库见 [credential-storage.md](credential-storage.md)。本文不出现任何真实口令，示例均为虚构、禁止照抄。

## 一、先纠正两个直觉错误

1. **"短 + 数字/符号/大小写" ≠ 好记又安全。** 类似 `abc12345`、`单词+出生年份` 这种短口令，字符空间小、又是常见模式，离线爆破和撞库都很快；人也并没有因此少记多少。
2. **"每个网站都用不同复杂密码、全靠脑子记"是错的方向。** 正确分工是：**脑子只记 1 句主口令，网站密码全部随机、交给密码管理器**（见 credential-storage.md 第五节）。

记忆负担最小化的终态：你只需要能默写一句主口令。

## 二、为什么"口令短语"又强又好记（长度 > 复杂度）

现代结论一致：**抗爆破主要靠长度（熵），不是靠把单个字符搞得很怪。** 一串随机挑选的普通词，比一串又短又怪的字符更难破、也更好背。

以 Diceware（掷骰从词表随机选词）为参考，使用 EFF 长词表（每词约 12.9 bit）：

| 词数 | 约等于熵 | 强度定位 |
|---|---|---|
| 3 词 | ~38 bit | **不够**，扛不住离线攻击 |
| 4 词 | ~52 bit | 约等于 8 位全字符随机密码，普通用途下限 |
| 5 词 | ~64 bit | 达到 NIST 对高保证 memorized secret 的熵门槛 |
| **6 词** | **~77 bit** | **EFF 对大多数口令短语用途的推荐值，建议主口令取这个量级** |
| 7 词 | ~90 bit | 主密码、银行、加密盘等更重要场景 |

> 关键：词必须**随机选**（掷骰/生成器），而不是自己顺着语感造一句话——人自己编的"随机"往往有规律、可预测。

## 三、造一句自己的主口令（两种方法）

### 方法 A：Diceware 随机词（最规范，推荐）

1. 用 EFF 长词表（https://www.eff.org/dice ，可配真实骰子或可信离线生成器）。
2. 随机选 **6 个词**，用空格或你顺手的分隔符连起来，例如（纯虚构，仅示意结构）：`outlast recolor magnetic finance clutch glaze`。
3. 默写几遍形成肌肉记忆；可加一个你固定的小变换（如每个词首字母大写、结尾加年份/符号），但**主体强度来自 6 个随机词，不靠这个小变换**。

### 方法 B：中文友好的"私人画面长句"（更好背，注意去可预测性）

中文母语者更适合记一句"有画面、但不合常理、只有你知道来历"的话，再做规则化：

构造步骤：
1. **私人化**：取自你真实经历里、网上查不到的细节（某段私人记忆、旧地址、只有你懂的绰号/梗），**不要**用名言、歌词、诗句、谚语、影视剧台词、网络流行语——这些都会进破解字典。
2. **画面化、荒诞化**：把几个不相干的意象强行拼在一起（越不合常理越难猜、反而越好记）。
3. **够长**：整句展开后 ≥ 20 个汉字/字符量级（对应 6 词口令短语的强度目标）。
4. **规则化取串**：取每字/每词首字母（拼音）或保留原字，加入你固定的分隔符、1 个数字、1 个符号、个别大小写，形成稳定可复现的规则——**规则可以固定，素材必须私人且随机**。
5. 自己能稳定默写、别人（哪怕熟人）猜不到，即为合格。

> 无论 A/B：**不要照抄任何示例**；不要把它用作任何网站的登录密码（它只用来解锁本地库，见下）。

合格性自检：
- [ ] 长度达到 6 词 / 20+ 字符量级
- [ ] 不含姓名、生日、手机号、常用单词+123 等可查信息
- [ ] 不是名言/歌词/常见句
- [ ] 你能在不看提示的情况下连续默写 3 次
- [ ] 已做离线纸质备份（第五节）

## 四、主口令可以"一处多用"吗

可以，但要分清"本地解锁点"和"在线网站"：

- **允许统一**：Mac 登录/sudo、磁盘/屏幕锁、SSH 私钥 passphrase、本地 `.enc` 解密口令、**密码管理器主密码**——这些都是"解锁你自己本地保管库"的点，口令不会被发送到任何网站服务器。为了可记忆，统一成同一句主口令是可接受的折中。
- **绝不允许**：把这句主口令当作任何**在线网站/App 的登录密码**。网站密码必须是密码管理器里随机生成、各不相同的。原因：网站可能被拖库，一旦它等于你的主口令，等于所有本地库一起失守。

一句话：**主口令只在本地出现，绝不上线；上线的密码全部随机、互不重复。**

## 五、离线备份：防的是"忘记"，不是黑客

主口令是所有库的根，**一旦彻底忘记，加密库和密码管理器在数学上无法找回**（这正是加密的意义，没有后门）。所以要做离线备份：

1. 把主口令**手写在纸上**（不要打印、不要存成电脑/手机文件、不要存进密码管理器自身——那是鸡生蛋）。
2. 纸放物理安全处：上锁的抽屉/保险柜/随身安全位置；可再加一层"只有你懂的改写"（如少写一段、用你自己的规则补全）。
3. 这张纸防的是**你自己遗忘/意外**，不是防远程黑客——离线纸张不联网，攻击面远小于任何数字副本。
4. 重大变更（改了主口令）同步更新纸条、销毁旧纸条。

## 六、从当前短弱口令迁移的渐进路线

不必一次性全改（容易把自己锁在外面）。按"先立后破、每步验证"推进：

1. **先定新主口令**并默写熟练 + 离线纸质备份。
2. **本地 `.enc` 凭证库**：用新口令把现有 `.enc` 逐个重新加密（解密旧的→用新口令加密覆盖；双机都要更新）。
3. **密码管理器**：装好管理器，把主密码设为新主口令，开始把网站密码逐步换成随机密码（先重要账号）。
4. **SSH 私钥 passphrase / macOS 登录密码**：再改这两处，改完验证 ssh-agent/钥匙串、sudo 正常。
5. 每改一处立即验证可用、确认能解锁，再进行下一步；旧口令在全部迁移完成、确认无遗漏前先别急着丢弃。

> 迁移涉及双机与具体凭证落点时，按 dual-machine-manager 的凭证轮换 SOP 执行，避免两台不一致。

## 七、多久换一次、什么情况必须换

- **不要为了"定期"而频繁换**：NIST 现行指南不再强制无依据的周期性更换——被迫常换反而会催生弱密码和写便签。
- **出现以下情况才必须换**：怀疑被看到/拍到/录到、某台机器中毒或失窃、对应库或网站发生泄漏、人员/设备不再可信、发现凭证已进公开仓或日志。
- 网站密码的"换"由密码管理器 + 网站泄漏告警辅助；主口令一旦更换，按第六节同步所有本地解锁点与离线备份。

## 八、常见问题

- **Q：密码管理器被攻破怎么办？**
  A：主流开源方案零知识加密，服务器只存密文，主口令不出本机；选有第三方审计、可自托管的方案（Bitwarden/KeePassXC），并给管理器本身开 2FA。风险远小于"一个弱密码走天下"。
- **Q：二步验证（2FA/TOTP）和主口令什么关系？**
  A：它是独立第二层。重要在线账号（邮箱、GitHub、云、支付、域名）在随机密码之外再开 TOTP 或硬件密钥；TOTP 可存密码管理器，更高要求用独立验证器/硬件 key。
- **Q：能不能用 Touch ID/面容代替记主口令？**
  A：可以作为日常快捷解锁（钥匙串、密码管理器都支持生物识别），但生物识别只是"免去频繁输入"，底层仍由主口令/密钥保护，所以主口令仍要记住并离线备份（重启/换机后要再输一次）。
- **Q：口令短语里要不要加大小写数字符号？**
  A：6 个随机词本身已够强，加符号是锦上添花、不是必需；真正不能省的是"随机 + 够长 + 私人不可预测"。
