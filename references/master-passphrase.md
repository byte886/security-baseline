# 人要记的口令：弱记忆友好方案（不靠强口令、不靠纸）

> 核心命题：**好的密码体系不该考验记忆力和输入耐心。** 目标不是"逼自己记住一句很强的口令"，而是用工具把"需要脑子记、需要手输"的场景压到最少；剩下极少数必须手输的点，用你**本来就记得住**的一档口令即可。
> 配套：各类凭证存哪见 [credential-storage.md](credential-storage.md)；AI/自动化用的密钥如何与人的密码分开见 [ai-agent-credentials.md](ai-agent-credentials.md)。本文不出现任何真实口令，示例均为虚构、禁止照抄。

## 一、先换思路：从"记住强口令"到"消除记和输"

传统建议（记一句 6 词、77bit 的强主口令、再写纸备份）在"每天要解锁几十次、又不爱用纸"的现实里会失败：口令太强→手输痛苦→要么改弱、要么延长自动锁定、要么写得到处都是，反而更不安全。

现代实践换了着力点，**优先消除"记"和"输"本身**：

1. **能 passkey 就不用密码**：指纹/面容/设备 PIN 登录，既不用记也不用输，还天然抗钓鱼（见第三节）。
2. **必须用密码的网站，交给密码管理器随机生成 + 自动填充**，日常用生物识别解锁管理器，主密码只在重启/换机等极少数时候手输一次（见第四节）。
3. **只有"本地解锁点"还需要你记一句口令**（Mac 登录/sudo、密码管理器主密码）。因为输入频率已被生物识别压到极低，它不必是难背的 6 词短语，用"记得住的中等强度"即可（见第五节）。
4. **AI/脚本用的密钥完全不占你的记忆**：走加密库 + 本机非交互取密，人不需要为自动化记口令（见 ai-agent-credentials.md）。

> 一句话：**先消灭"要记/要输"的账户数量，再谈剩下那句口令多强——顺序不能反。**

## 二、三层分流：哪些彻底不用记，哪些还要

| 层 | 对象 | 怎么登录 | 你要记/要输吗 |
|---|---|---|---|
| **A 免密层** | 支持 passkey 的重要在线账户（Google、GitHub、微软、主邮箱、云、多数银行/社交） | 手机指纹/面容，或设备 PIN；电脑上用手机扫码跨设备认证 | **完全不记、不输密码**（旧密码保留作兜底） |
| **B 托管层** | 还不支持 passkey 的网站/App | 密码管理器随机 16+ 位密码，浏览器/手机自动填充；解锁管理器用生物识别 | 不记；**每天也基本不用手输主密码**（指纹代劳） |
| **C 本地层** | Mac 登录/sudo/锁屏、SSH 私钥 passphrase、`.enc` 解密口令、密码管理器主密码 | 手输（本地、不发往任何服务器） | **唯一要记的一类**，几处可统一成同一句"记得住的中等口令" |

记忆负担的终态：**你只需要稳定记住 C 层那一句**；A 层靠身体（指纹），B 层靠管理器，AI 层靠加密库。

## 三、在线账户：passkey 优先，免记免输

passkey（通行密钥 / FIDO2 WebAuthn）是 2026 年替代密码的主线，特性正好解决"记不住、输着烦"：

- **用指纹/面容/设备 PIN 解锁**，没有可背的密码；
- **抗钓鱼**：密钥与真实域名绑定，假登录页什么也拿不到；
- **服务端只存公钥**，网站被拖库也泄不出可用凭证；通常**不再需要单独的短信/TOTP 验证码**（passkey 本身已是强第二因素）；
- **旧密码不会被删、仍可作备份登录**，不会因为开了 passkey 就把自己锁在外面。

落地做法（适配"安卓手机 + 两台无指纹黑苹果 Mac"）：

1. **手机端**：在重要账户的安全设置里"创建 passkey"，存到系统密码管理器（Android 用 **Google 密码管理器**作 passkey 提供方；也可用 Microsoft Authenticator 作 passkey 提供方，需 Android 14+）。
2. **无指纹的 Mac/台式机**：登录时选"使用手机/安全密钥"，屏幕出 **QR 码 → 用安卓手机扫码 → 手机上指纹确认**，经蓝牙近场完成（FIDO 跨设备认证，标准能力，需两设备都开蓝牙+联网）。所以黑苹果没有 Touch ID 也不影响。
3. **重要账户各配 2 份 passkey**（如主力手机一份、另一台设备/安全密钥一份），任一可用即可登录，降低"一台设备丢了就锁出"。
4. 优先级：主邮箱（它能重置其它一切）> GitHub（已开 2FA，可直接升级 passkey）> 微软/云 > 支付/银行 > 其它。

> 你已装的 **Microsoft Authenticator**：仍可做 **TOTP 动态验证码**和 **passkey 提供方**；但其"密码自动填充"功能已于 2025 年 8 月停用（已存密码改由 Microsoft Edge 管理）。**不要再指望用它当全平台密码管理器**，密码托管用第四节的方案。

## 四、不支持 passkey 的：随机密码 + 生物识别自动填

剩下的网站不自己想密码：

1. 用一个**跨平台密码管理器**为每个网站生成 16+ 位随机、互不重复的密码，浏览器扩展/手机自动填充（选型见 [credential-storage.md](credential-storage.md) 第五节，个人免费场景主线为 Bitwarden）。
2. **开启生物识别解锁**（手机指纹、Mac 端在支持时用 Touch ID/系统密码代填）。这样主密码只在"设备重启、新装客户端、偶尔重验"时才手输，日常几十次解锁都由指纹完成——**这是"主密码不必难背"的前提**。
3. 自动锁定时间设成你能接受的值（如几分钟/锁屏时锁），不要为了少输而设成"永不锁定"。
4. **TOTP 动态验证码继续用 Microsoft Authenticator**（免费、独立 App），与密码管理器分工：管理器管密码、Authenticator 管动态码，零成本，也避免把"密码+第二因素"全塞进同一个库。

## 五、你真正要记的口令：只要"记得住的中等强度"

C 层那几处（Mac 登录/sudo、SSH 私钥 passphrase、`.enc` 解密、密码管理器主密码）可以统一成**同一句**，因为它们都只在本地、不发往任何网站。对它的要求是"**你能脱口而出、又明显强于常见弱口令**"，而不是 6 词随机短语。

**务实标准（弱记忆友好）：**

- 长度 **≥ 12～14 个字符**；
- 字母 + 数字（可再带 1 个符号/大小写，但别为了符号牺牲好记）；
- **不是**词典单词、常见短语、`名字/拼音 + 生日/年份/123`、也不是任何网站在用的密码；
- 带一段**只有你知道来历的私人片段**（早年绰号、旧地址、私人梗），你天然记得、别人和字典都查不到。
- 结构示例（**纯虚构、只示意思路，禁止照抄**）：一个私人词 + 另一个不相干私人词 + 一段好记数字，整体能一口气打完。

**为什么这个强度对你可接受（诚实标注边界）：**

- 主密码最强的攻击场景是"**加密库文件被人拷走、离线无限次爆破**"。正统建议因此要求 6 词 ≈77bit。
- 但在你的现实里：库不主动外发、设备是固定场所的个人机器、日常靠生物识别解锁、这句口令**从不在任何网站复用**——在线撞库/拖库打不到它，离线拿到库文件的概率很低。用一句 12～14 位、非词典、带私人熵的口令，相对短弱口令是数量级的提升，是"个人可用性 vs 理论极限"的合理折中。
- **什么情况下要回到更强（更长/随机词）**：你要把密码库文件放到不完全信任的云、设备常带出门有丢失风险、或这一句需要在多人环境频繁手输。届时再按 EFF Diceware 加长即可（见来源），方案不冲突。

> 红线不变：这句 C 层口令**只在本地出现，绝不当任何网站密码**；网站密码一律随机、互不重复。

## 六、不用纸：靠数字冗余防遗忘、防锁出

不依赖纸质备份，改用"多份数字冗余 + 账户自身找回"：

1. **密码库多设备同步本身就是冗余**：手机 + 两台 Mac 都登录同一密码库，任一设备损坏/丢失，其它设备仍在，不会因单点故障丢库。
2. **2FA/账户恢复码存进密码库**：给某账户开 2FA/passkey 时拿到的恢复码（recovery codes），作为该条目"安全笔记"存进密码管理器（加密、跨设备同步、不依赖那张纸/那部手机）。
3. **密码管理器"自身"的恢复不能靠它自己（鸡生蛋）**，用这三道：① 多台设备保持登录作为活冗余；② 主密码就是第五节那句你记得住的口令（不依赖纸也能想起）；③ 可选——把恢复方式以加密形式交给一位你信任的人，或存于你另一个独立的安全位置（不是明文便签）。
4. **重要账户多配 passkey / 多种第二因素**（手机 + 另一设备或安全密钥），并确保主邮箱本身可恢复——主邮箱是绝大多数账户"忘记密码"找回链路的根。
5. 定期（如每季度）花十分钟做一次"**假装失忆演练**"：不带提示能否解锁密码库、能否用第二台设备登录重要账户，发现缺口当场补。

## 七、本机登录 / sudo 口令怎么看（务实，不折腾）

- Mac 登录/sudo 口令的主要威胁是**有人物理接触这台机器**，而不是网络爆破。固定场所、不常移动的台式黑苹果，该风险等级本就不高。
- 真正防"机器/硬盘被拿走"的是 **FileVault 全盘加密**（系统设置里开启），以及关闭自动登录、离开自动锁屏——这两项比把登录口令设得又长又难打更有效。
- 因此：**不强制**把登录口令改成难背的串；若愿意小幅升级，统一成第五节那句"记得住的中等口令"即可，两台机器一致更省心。是否升级、何时升级由你决定，技能不催。
- SSH 私钥 passphrase 可与登录口令一致，并交给 ssh-agent/钥匙串，避免每次手输（双机配置见 dual-machine-manager）。

## 八、迁移路线（分步、先立后破、不锁出）

不要一次性全改，按下面顺序、每步验证后再下一步：

1. **先上 passkey**：给主邮箱、GitHub、微软账号创建 passkey（手机），验证能用指纹/扫码登录，旧密码先保留。
2. **装密码管理器、开生物识别**：主密码先设成第五节那句你确定记得牢的口令；先把最重要账户录入并换成随机密码。
3. **其余网站随用随换**：登录到哪个就顺手让管理器生成新随机密码，不专门花一天批量改。
4. **TOTP 归位**：需要动态码的继续用 Microsoft Authenticator；恢复码抄进管理器对应条目。
5. **最后才动本地层**：愿意的话把 Mac 登录/sudo、SSH passphrase、`.enc` 解密口令统一到 C 层那句；`.enc` 需用新口令逐个重新加密、双机都更新（轮换 SOP 见 dual-machine-manager）。
6. 任一步没验证通过就停在该步，旧口令/旧密码在确认无遗漏前不删除。

## 九、多久换一次

- **不为"定期"而换**：NIST 现行指南不强制无依据的周期更换，被迫常换反而催生弱密码和便签。
- **这些情况必须换**：怀疑被看到/拍到、设备中毒或失窃、某网站拖库且你复用了密码、凭证误入公开仓/日志/聊天、设备或人员不再可信。
- passkey 怀疑失窃时在该账户安全设置里删除对应 passkey 再重建即可，不影响其它设备。

## 十、常见问题

- **Q：那到底还要不要密码管理器主密码？用指纹不行吗？**
  A：生物识别是"免去频繁输入"，底层库仍由主密码保护（重启/换机/新客户端要输一次）。所以这句仍要记得，但因为几乎不手输，用第五节"记得住的中等强度"即可，不必难背。
- **Q：Microsoft Authenticator 不是能存密码吗？**
  A：它的密码自动填充已于 2025 年 8 月停用（密码归 Microsoft Edge 管）；现在用它做 TOTP 动态码和 passkey。全平台密码托管另用密码管理器。
- **Q：黑苹果没指纹，passkey 是不是用不了？**
  A：能用。电脑登录页选"用手机/安全密钥"，安卓扫码 + 手机指纹确认即可（需蓝牙近场）。
- **Q：密码管理器被攻破怎么办？**
  A：主流方案零知识加密、服务器只存密文、主密码不出本机，并有第三方审计；再给管理器本身开第二因素。风险远小于"一个密码走天下"。
- **Q：完全不想让密码上任何云？**
  A：退而用 KeePassXC 本地库（KDBX），自己在设备间同步库文件；代价是要自己管同步，与"简单"目标相悖，个人一般不必。
