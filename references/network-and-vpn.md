## 一、总原则：以连通性为准，不硬等不可达资源

1. 需要访问 Google、Brave、部分 GitHub/境外文档等资源时，**先做一次快速连通性测试**（如 `curl -I -m 3 https://www.google.com`，限时约 3 秒）。
2. 通 → 正常用境外渠道；不通 → 挂代理后再测；代理也不通 → **改用国内可达渠道**（百度、必应国内版、专业数据库、官方镜像），不反复重试、不强访不可用资源。
3. 代理是"可达性工具"，不是"安全开关"——它解决能不能连上，不自动保证内容不泄漏（见第四节）。

## 二、终端怎么临时走代理

代理客户端通常同时提供 HTTP(S) 与 SOCKS5 端口，在当前 shell 导出环境变量即可（端口以现场探测为准，下例为常见值）：

```bash
# 当前终端会话走代理（示例端口，实际以探测到的为准）
export https_proxy=http://127.0.0.1:7897
export http_proxy=http://127.0.0.1:7897
export all_proxy=socks5://127.0.0.1:7897

# 验证出口是否已走代理（看返回 IP/地区是否变化）
curl -m 5 https://api.ip.sb/geoip || curl -m 5 https://ipinfo.io

# 用完取消，避免后续请求都绕代理
unset https_proxy http_proxy all_proxy
```

- 只影响**当前 shell 会话**，不开全局，最干净；需要长期可写进专用 alias/函数按需启用，不默认全开。
- `git`/`gh`/`brew`/`npm` 等是否跟随上述变量各有差异，具体配置交给 mac-system-toolkit 的代理能力；主仓实际统一走 SSH（`ssh.github.com:443`），不依赖 HTTP 代理。

## 三、端口不写死，先探测

- 不同客户端默认端口不同（如 ClashX 常见 7890、Clash Verge 常见 7897），且可能被改过；**双机环境下两台机器装的客户端还可能不一样（一台 ClashX、一台 Clash Verge），端口随之不同**。
- **禁止把某个端口写死进脚本/文档当事实**，也不能拿文档或台账里的旧端口替代现场探测：每次先探测当前客户端的 `mixed-port`/`http-port`/`socks-port`（探测与切换是 mac-system-toolkit 的代理能力）。
- "哪台机装了什么客户端、常态端口多少"属资产台账，记在 dual-machine-manager；台账只用于快速预判，真正使用仍以当场探测结果为准。

## 四、走代理/VPN 的安全边界

1. **可信通道原则**：只用自己的、或明确可信的代理/VPN 服务。免费公共 VPN/开放代理可能记录甚至篡改**未加密**流量。
2. **HTTPS 内容仍端到端加密**：即使经过代理，HTTPS 的正文对方也看不到；但代理方仍可能看到**目标域名（SNI）、DNS 查询、连接时间与流量元数据**——所以不要假设"挂了代理就完全匿名"。
3. **敏感凭证不因挂代理而放松**：含明文 token/密码的请求，确认目标是 HTTPS 官方域名；绝不在明文 HTTP 页面传凭证；不明来源的代理证书告警要警惕（可能是中间人），不要一路"信任"。
4. **公共 Wi-Fi**：优先使用蜂窝网络或可信 VPN；坚持 HTTPS；避免在公共网络做敏感登录/支付，确需进行时用二步验证。
5. **DNS 泄漏 / Kill Switch**：关注代理是否接管 DNS（否则"代理了流量没代理 DNS"仍暴露访问目标）；客户端若有 Kill Switch（断网即断连，防止代理掉线后裸奔）建议开启。
6. 代理/VPN 配置本身不含秘密时可入库；**订阅地址、账号密码、节点凭证等同属敏感凭证**，按 [credential-storage.md](credential-storage.md) 加密保存，不明文进公开仓。

## 五、AI Agent 的检索渠道决策（指针）

```
要检索外部信息
│
├─ 医疗/法律/金融等专业领域？
│    └─ 优先权威数据库/官方来源，不以普通网页替代（用户全局规则）
│
├─ 目标是境外站点？
│    ├─ curl 限时测试连通
│    ├─ 通 → 直接用（Google/Brave/官方文档优先）
│    └─ 不通 → 探测端口→当前 shell 导代理→再测；仍不通转国内可达渠道
│
└─ 目标国内可达？
     └─ 直接用国内渠道，不必为"用 Google"而强行挂代理
```

- 代理的开/关、端口探测、菜单栏操作等**动作层**统一交给 mac-system-toolkit 的代理与桌面控制能力；本技能只决定"该不该用、用的时候注意什么"。
- 两台机器各自的代理客户端、端口等**台账事实**记在 dual-machine-manager，不在此固化。

## 六、常见问题

- **Q：导出了环境变量为什么 git 还是慢/不通？**
  A：主仓走 SSH（443），不看 `http(s)_proxy`；确需让某工具走代理，按该工具自身代理配置处理（用 mac-system-toolkit 代理能力）。
- **Q：怎么确认代理真的生效而不是"假通"？**
  A：对比挂代理前后的出口 IP（第二节命令）；出口 IP/地区变化才说明生效。
- **Q：挂了代理是不是就能安全地传 token？**
  A：不是。传输安全取决于 HTTPS 与目标可信度；代理只改路由，凭证仍按本技能红线加密、不外露。
- **Q：代理订阅链接算敏感信息吗？**
  A：算（可被用来蹭用/关联你的节点），按凭证加密保存，不进公开仓明文。
